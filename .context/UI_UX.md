# UI/UX 설계 기준

## 구조

- 홈: **AI와 플레이 / 사람과 플레이(같은 기기, 2인)** 두 선택지. 과도한 소개 문구 없음.
- 플레이: 상단 최소 내비게이션, 왼쪽 참가자, 중앙 넓은 테이블, 하단 2줄 랙, 오른쪽 뽑기/취소/완료.
- AI 비교: 연구 실험과 모델 설명. 플레이 화면에 연구 수치 노출하지 않음.
- 광고·가짜 3D·광택·그라데이션·글로우·강한 그림자 없음. 흰 타일과 단색 파란 테이블, 선명한 숫자만.
- 테이블 조합은 인접하게 촘촘히 정렬하며 작은 화면에서는 랙과 조작 버튼을 압축.

## AI 대국 관전

- 홈의 **AI 대국 관전**과 상단 독립 탭 제공; 플레이 UX와 연구 UX 분리.
- 두 모델 선택, 재생/일시정지/한 턴 진행/배속, 같은 시드 재생/새 시드, 턴 결과·승자·타일 개수.
- 기본은 테이블 중심. 두 AI의 손패는 사용자가 **손패 보기**를 켰을 때만 연구용으로 펼침.
- 모델 간 비교는 어떤 두 모델이든 같은 시드와 선후공 교환으로 재현 가능. 소수 대국에서 우열 확정 문구를 쓰지 않음.

## 2026-11-23 사용자 최신 미완료 UX 요구 (이전 가이드보다 우선)

- **관전 양쪽 손패**: AI A·B가 실제로 보유한 타일을 한눈에 알아보기 쉽게 표시하는 방향으로 변경. 일반 플레이의 상대 손패 비공개 규칙은 유지. 관전에서 손패 표시를 켜는 기능은 이미 있지만 레이아웃·가독성 개선은 미완료.
- **행동 단계 애니메이션**: AI가 낼 패를 선택·집기→테이블로 이동→기존 타일 재배열→놓기; 뽑을 때는 더미→해당 랙 맨 끝으로 이동, 새 타일 강조. 각 단계가 타일의 실제 이전/이후 위치와 일치해야 함. 아직 미구현.
- **초기화 느낌 금지**: AI 행동 때마다 `root.innerHTML` 전체 재생성하여 페이지 스크롤이 맨 위로 튀고 `select`가 닫히는 문제 해결. 부분 갱신 또는 키 안정화, 포커스와 설정 상태 유지, 브라우저 E2E 검증 필수. 아직 미해결.
- **뽑은 타일 순서 보존**: `drawFor()`는 손패에 push하지만 `resetDraft()`가 턴마다 정렬함. 새 카드가 이전 정렬에 자동 합류하지 않게 해야 함. 새로 뽑은 타일은 **맨 뒤에 뽑힌 순서로 유지**, 사용자가 정렬 버튼을 누를 때만 전체 정렬. 아직 미해결.
- 이전 '관전에서 손패는 기본 숨김' 지침보다 **양쪽 AI 타일을 실제로 보면서 움직임을 관찰하고 싶다는 최신 요청**이 우선. 일반 플레이 UI에 불필요한 수치나 설명을 늘리지 말 것.

## 타일 조작

- 짧게 클릭: 단일 선택. 짧게 드래그: 단일 또는 이미 선택한 묶음 이동.
- **길게 누르기(약 330ms)**: 현재 타일에서 시작해 같은 랙 줄(또는 같은 테이블 조합)의 **바로 오른쪽 연속 타일**만 자동 선택. 조합을 깨는 타일에서 즉시 중단. 떨어져 있는 타일은 자동으로 찾지 않는다.
- 같은 색 연속 숫자 및 같은 숫자 다른 색의 그룹을 인식. 조커도 연속 조합에 들어갈 수 있다.
- 현재 손패에 유효하게 없는 임의의 조합을 자동 생성하지 않는다.
- 기존 조합에 타일을 놓으면 **뒤에 추가**, 전체 조합이 법적으로 유효해지는 순서가 있다면 자동 정렬한다.
- 미완성 임시 배치를 허용하지만 턴 완료는 전체 테이블·첫 등록·타일 보존 검증 후 확정.
- 되돌리기/다시 실행, 턴 전체 초기화, 소리 켜기/끄기.

## 사람 대 사람

- 동일 브라우저에서 번갈아 진행한다. 차례 전환 시 손패를 가리는 준비 화면을 표시.
- 이 기능은 온라인 멀티플레이를 뜻하지 않는다. 친구 초대/원격 플레이는 후속 과제.

## 평가해야 할 항목

- 첫 조합 생성 시간, 드롭 실패율, 잘못된 조합 경고, 되돌리기 비율, 모바일 탭/드래그 성공률.
- 데스크톱 최소 일반 해상도·모바일 가로세로·키보드 단축키.

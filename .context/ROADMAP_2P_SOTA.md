# RummikubAI — 2인전 SOTA 연구·제품 통합 계획

> 2026-11-23 기획 기준. 이 문서는 **확정 연구 목표와 구현·검증 계획**이지, 아래 모델의 구현 완료 또는 SOTA 입증을 의미하지 않는다.

## 0. 최상위 목표와 범위

- 연구 대상: **2인전 클래식 루미큐브**, 타일 106개(숫자 104개 + 조커 2개), 최초 손패 14개, 첫 등록 30점. 공식 규칙의 조커 회수/재배열, 더미 고갈, 끝내기/무승부 등은 버전으로 고정한다.
- 최적화 목적: 한 턴의 타일 사용량이 아닌 **최종 승리 확률**. 부차 지표는 잔여 타일 패널티·생존 턴 수·추론 비용·합법 행동 비율.
- 3/4인전, 온라인 인간 매칭, 커스텀 룰은 연구 범위 밖(서비스 기능은 유지 가능).
- 각 학습/탐색법을 **별도 모델 또는 검증 가능한 ablation**으로 구현한다. 전부를 하나의 모델에 억지 결합하지 않는다.
- 표준화된 외부 2인전 루미큐브 SOTA 리더보드는 확인되지 않았음. 내부 모델에 대한 우위만으로 세계 최고를 주장하지 않는다.

## 1. 현재 출발점

- 기존 6종: Random / Greedy / Joker Guard / Exact Small / Strategic v1.1 / Strategic+ v1.
- 2026-11-23 기록: Strategic+ vs Strategic v1.1, **200판 127승 73패** (63.5%, 같은 시드 선후공 교대, **동일 추론시간은 아님**). 출처: `AI_RESEARCH.md`.
- 게임 로직은 `engine.js`, 관전 상태는 `spectator.js`, 화면은 `app.js`, 랙/테이블 임시 이동은 `draft.js`, 비교는 `bench/matchup.mjs`.
- 확인된 기술 부채: 관전 `render()`에서 전체 root HTML 재생성; 게임 랙 초기화 시 `sortDraftRack(startDraft(...))`로 자동 정렬. 이는 화면 스크롤·드롭다운 유지, 뽑기 순서 보존 요구와 충돌.

## 2. 우선 구축할 연구 인프라 (P0)

1. **공식 룰 사양 고정**: 조커 대체·반환, 첫 등록, 게임 종료·더미 고갈, 물리 타일 ID 보존, 합법/불법 조합을 별도 오라클 및 속성 기반 테스트로 검증. 규칙 버전/seed 기록.
2. **완전정보 상태와 플레이어 관측 분리**: `FullState`는 시뮬레이터·관전에만, `PlayerObservation`은 해당 AI의 손패, 보드, 공개 이력, 상대 장수, 더미 개수만 포함. 상대 손패/더미 순서 접근 여부를 테스트. 관전에서 손패 공개해도 AI에게 누설되지 않음.
3. **행동 API 표준화**: `draw`, `rack-meld`, `board-extend`, `rearrange`, `joker-replace` 등의 합법 행동을 타일 ID·최종 보드 상태로 직렬화. 단순히 mutate하는 엔진보다 후보 생성/적용/검증/설명의 단계를 분리.
4. **공정한 대국 파이프라인**: 같은 시드로 좌석을 교환한 짝(pair)을 분석 단위로 사용. 사전 확정 학습/검증/최종 테스트 시드 분리. 0.3초/1초/3초 등 **동일 CPU 벽시계 예산**, seed별 승패/무/계산시간/노드/행동 합법성 기록. 신뢰구간은 seed 쌍 단위 bootstrap, 필요하면 SPRT·Elo 사용. 초반 20/40판 UI 시범 대국을 연구 확증과 구분.
5. **리그 벤치마크**: 약한 기준선뿐 아니라 지난 최강 모델과도 비교. 동일 시간·동일 자원, 버전·해시·설정 고정. 모델이 이전 모델을 대체하려면 독립 시드에서 일관된 개선을 제시.

## 3. 연구 후보: 전부 실험하되 단계별로

| 단계 | 방법 | 루미큐브 적용 | 검증/주요 위험 |
| --- | --- | --- | --- |
| P1 | Global Exact Cover / ILP / CP-SAT / B&B | 현 보드 유지 조건으로 가능한 **상위 K개의 서로 다른 합법적 턴 결과**를 생성, 조커·동형 타일 대칭성 제거, 시간 초과 시 anytime 대안 | 솔버 정답률·시간·후보 다양성; 1턴 최적성 ≠ 승률 |
| P2 | Belief sampling / determinization baseline | 공개 타일과 행동 이력에 맞게 상대 패·더미 후보 샘플링 | 숨은 정보 누출 및 strategy fusion 주의 |
| P2 | ISMCTS / POMCP 성격의 정보집합 탐색 | 믿음 상태 샘플을 탐색에 사용, Strategic+ 또는 신규 솔버 기반 rollout, 여러 관측에서 재사용 가능한 정책 | 같은 추론 시간으로 Strong Baseline과 비교; 결정화 편향 확인 |
| P3 | Expert Iteration (ExIt) / policy distillation | 강한 솔버+정보집합 탐색을 교사로, 상태→정책/가치망 학습. self-play 후 재탐색·학습 반복 | 학습과 평가 seed 격리, teacher보다 실제로 강해지는지 검증 |
| P3 | AlphaZero식 PUCT | 학습한 정책 prior/가치망으로 합법 행동 후보 탐색. 상대 관측은 belief-aware 구조로 확장 | 원형 AlphaZero는 완전정보 전제라 그대로 적용 불가 |
| P4 | Deep CFR / ReBeL | 2인 제로섬 효용에서 축소 게임·제한된 후보 추상화부터 구현, regret/belief 기반 해결 | 실제 전체 106개 게임으로 스케일 가능한지 비용/메모리 판단 |
| P4 | MuZero식 learned dynamics | 정확한 규칙 시뮬레이터 대비 learned model의 효율성·성능 ablation | 규칙을 이미 알기 때문에 우선순위 낮음. 오차 누적 위험 |

- **우선 실전 주력 경로:** Global turn solver → ISMCTS(+belief) → ExIt(정책·가치) → belief-aware PUCT hybrid.
- Deep CFR/ReBeL/MuZero는 **폐기하지 않고** 독립 연구 브랜치/축소 게임에서 비교하며 충분한 근거가 있을 때만 주력 모델로 통합.
- 단계는 하드한 달력 약속이 아니라 **검증 게이트**. 이전 단계의 합법성·성능 검증이 실패하면 다음 단계로 성급하게 넘어가지 않는다.

## 4. 사용자 요청: 관전 UI와 애니메이션 (P0/P1)

- 관전에서 **AI 양쪽 손패를 기본으로 읽기 쉽게 표시**(연구용), 테이블 중앙, 누가 행동 중인지 프로필만 강조.
- 행동을 `turn-start → select → lift → move/rearrange 또는 draw → settle → turn-end` 이벤트로 분해. 단계마다 실제 타일 ID와 출발/도착 좌표를 명시.
- **타일 뽑기:** 더미→현재 AI 랙 **맨 뒤**로 이동, 새 타일을 짧게 강조. 인접 정렬 규칙에 자동 삽입 금지. 여러 장이면 뽑은 순서 그대로 누적.
- **명시적인 정렬 버튼을 눌렀을 때만** 색상/숫자순 전체 손패 정렬. 턴 시작, 뽑기, AI의 패 내기마다 자동 정렬하지 않는다.
- **패 내기:** 선택된 타일 표시→랙에서 이탈→보드 조합 위치로 이동→기존 조합 재배열을 FLIP류 애니메이션으로 보간. 뽑기/선택/이동/놓기·사운드 타이밍 연동.
- **페이지 재생성 금지:** 기존 `root.innerHTML` 전체 교체 대신 안정된 컴포넌트/키·부분 갱신. 관전 중 스크롤·포커스·열린 드롭다운·속도/일시정지 설정 유지. 화면 상단으로 튀지 않게 함.
- **관전 기록:** 턴별 행동 타임라인/플레이어·모델·점수/배치 타일, 클릭하면 해당 시점 재생. 연구 정보(탐색 후보 수·탐색시간·선택 이유)는 기본 숨김/연구 모드로 표시.
- 재생/일시정지, 한 턴 진행, 속도 조절, 동일 seed 재생, 다음 seed, 효과음 음소거, 모바일 이용성 유지.

## 5. 사용자 요청: 실제 플레이 UI·규칙·프로젝트 운영

- 홈에서 **AI와 플레이 / 사람과 플레이(같은 기기 2인)** 선택. 온라인 실시간 대전과 혼동하지 않음.
- 깔끔한 **단색 파란 테이블 / 큰 흰색 타일 / 하단 랙 / 좌측 상대 / 우측 3개 주요 버튼**, 불필요한 상시 정보·빛 효과·글로우·그라데이션 제거.
- 타일을 길게 누르면 **누른 타일부터 같은 줄/조합의 바로 뒤쪽 유효하게 이어지는 타일만 자동 묶기**, 손패 전체에서 떨어진 조합 탐색이나 모든 지나가는 타일 무조건 묶기는 하지 않음.
- 기존 조합에 타일 추가 시 일단 끝에 붙인 뒤 합법적 완성 조합이면 **숫자/색 규칙에 맞게 자동 정렬**. 기존 테이블의 유효성 및 첫 등록 30점 유지.
- Undo/Redo·터치 드래그·휠 확대·조작 효과음·알림 최소화·로컬 2인전 턴 전환 시 상대 패 숨김 유지.
- `.context/`에 연구 계획, 구현 상태, 결정 및 실험 결과를 PR마다 갱신. 연구 실행은 가능한 기존 GitHub Actions에서 **수동·명시적 비용 한도** 우선. 

## 6. 첫 구현/실험 완료 조건

- 공식 룰/숨은 정보 경계 및 랙 정렬/타일 보존 속성 테스트 통과.
- 패 뽑기 순서·스크롤/드롭다운 유지·이동 애니메이션에 대한 브라우저 E2E 테스트 통과.
- 각 모델마다 별도 구현, 동일 시드·짝지은 자리 교환, 공통 계산 예산, 통계 결과와 로그/재현 명령 제공.
- 기존 최강 Strategic+ 대비 모델별 A/B 및 ablation. **승리한 모델만 주력으로 채택**하되 통계적 불확실성을 항상 표시.
- 외부 공개 루미큐브 AI/논문과 규칙·성능지표·코드의 일치가 확인되어야만 SOTA 주장.

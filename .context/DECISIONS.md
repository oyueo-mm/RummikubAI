# 설계 변경 기록

## 2026-11-23 · v0.6 UI/게임/연구 재설계

- **근거:** 공식 웹 루미큐브 참고 스크린샷에서 상대 위치, 중앙의 여러 행으로 정돈된 조합, 하단 랙이 핵심. 기존 구현은 비율·간격·조합 정렬이 어색했음.
- **롱프레스:** 예전 자동 전역 조합 탐색(v0.4)은 손패 전체에서 떨어진 타일까지 가져왔고, v0.5는 손가락이 지난 모든 타일을 규칙 없이 묶었음. 사용자 수정 요구에 따라 **누른 타일부터 물리적으로 오른쪽에 연속된 합법 후보만** 선택하기로 결정.
- **드롭 후 정리:** 기존 조합의 끝에 타일을 넣고, 합법적 완성 조합이 될 수 있다면 자동으로 재정렬. 불완성 상태는 임시 보존.
- **홈:** AI와 플레이와 사람과 플레이를 처음부터 명시. 로컬 대전은 바로 구현하고 온라인 대전은 추후 별도로 설계.
- **AI:** Greedy를 무작정 강한 모델이라고 부르지 않고, 제한된 정확 탐색을 추가해 독립 비교 가능한 새 전략으로 제공. 40판 비교에서 기존 v1은 차이가 없었으므로 v1.1에는 **큰 보드의 국소 Exact Cover**를 추가. 그 결과 40판 40승 및 독립 120판 116승을 관측했지만 SOTA나 보편적 최적성으로 해석하지 않음. 성능 우위는 측정 전 미확정.
- **운영:** 이전 대화 맥락을 GitHub의 `.context/` 문서에 기록하고 변경 PR마다 함께 갱신.

## 2026-11-23 · v0.7 관전/모델 연구실

- 사용자 목표는 단순한 휴리스틱 AI 웹게임이 아니라 **루미큐브의 강력한 AI를 연구하고 궁극적으로 SOTA를 도전하는 것**.
- AI 대국 관전을 플레이와 분리. 두 모델을 선택하고 속도·한 턴 진행·동일 시드 재생·손패 공개를 지원.
- 서로 다른 실제 전략(기본, 조커 보존, 제한적 정확 탐색, 국소 탐색 확대)을 명시하고 단순한 이름 변경으로 모델 수를 부풀리지 않음.
- 임의 두 모델을 동일 시드로 선후공 교환하며 비교, 실험/공개 UI 결과와 벤치마크 스크립트를 일치.
- Strategic+의 탐색 예산 증가는 계산시간을 늘릴 수 있다. 성능 실험 전에 기존 Strategic보다 강하다고 단언하지 않음.
- 경쟁 SOTA는 **공식/공개 벤치마크와 규칙의 일치**를 확인하기 전까지 미확정.

## 2026-11-23 19:53 KST · 다음 채팅 인수인계 확정

- 가장 중요한 목표를 **2인전 최종 승률 최대화 및 SOTA급 연구**로 고정. 모든 기법(Global Exact Solver/ILP/CP-SAT/B&B, belief/ISMCTS, ExIt, AlphaZero식 PUCT, Deep CFR, ReBeL, MuZero)을 **실험 대상**으로 유지하되, 모두 즉시 하나로 합치거나 성능 입증 없이 SOTA라 부르지 않는다.
- 사용자의 마지막 미완료 UI 요구: 관전 전체 렌더링으로 인한 스크롤/드롭다운 초기화 해결, 뽑은 타일의 랙 맨 끝 순서 보존, AI 손패·선택·뽑기·이동·재배열 애니메이션 개선. `.context/BACKLOG.md`에서 P0로 분류.
- 예전 `STATUS.md`의 'PR #6 배포 전'은 실제 병합/배포 완료와 일치하지 않아 수정한다. 이전 릴리스 이력과 새 미완료 요구사항을 분리해 저장.
- 새 채팅 시작점 `.context/NEXT_CHAT.md` 추가; 모든 개발 세션은 인수인계·현재 코드·미완료 체크리스트를 검토한 뒤 수정한다.

## 2026-11-23 · P0 후속 안정화 구현

- 스크롤/드롭다운 재설정을 제거하기 위해 관전 탭이 살아 있는 동안 모델 select DOM 및 관전 컨테이너는 보존하고 게임판·손패·기록만 부분 갱신한다.
- 사용자 최신 요청에 따라 관전 두 AI 손패를 기본 공개하며 실제 게임에서 상대 손패는 계속 비공개이다.
- 타일 재생 타임라인은 관전 전용 완전정보 스냅샷으로 저장하며, AI 전략은 변경하지 않는다. tile ID에 따라 FLIP 위치 이동을 표시한다.
- 수동 랙 배치와 정렬 결과는 타일 뽑기 전 게임 랙 순서로 동기화하고, 뽑기는 끝에 추가한다. 턴 경계 재정렬은 중단한다.
- 브라우저에서 네이티브 select 열린 상태를 자동 확인하지 않은 코드는 E2E 완료로 표시하지 않는다.

## 2026-11-23 · 불완전정보 및 시드 쌍 실험 계측

- `PlayerObservation`은 현재 AI의 물리 타일 정보와 공개 테이블, 상대 패 개수, 더미 개수 등으로 제한하며 불변 복제해 원본 상태에 대한 읽기/쓰기 우회를 예방한다.
- 게임 상태 수정·타일 배분은 시뮬레이터가 소유한다. 모든 전략의 완전한 정책/행동 API 분리는 후속 단계.
- 승률 신뢰구간은 2경기를 한 시드로 취급하는 paired bootstrap을 사용. 1판을 독립 시드로 취급하지 않는다.
- 시간 측정은 실제 모델 계산량의 불균형을 드러내는 계측일 뿐 아직 공정 시간 예산을 제공하는 것이 아니다.
